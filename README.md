# OSRM خاص فينا — وصلني

خدمة حساب المسار الفعلي عبر الطرق (بدل خط مستقيم بين نقاط)، مستخدمة
من صفحة خريطة يبرود (ريبو `yabroud-bus-system-map`). خاص فينا بالكامل
بدل الاعتماد على خدمة خارجية (OpenRouteService الحالية).

## ⚠️ نقطة صراحة مهمة

الملفات هون (Docker Compose + سكريبت التجهيز) بتتبع **نفس الخطوات
الرسمية الموثقة من OSRM نفسها** — مش شي مبتكر أو مجرّب أول مرة. بس
**ما تم تشغيلها فعلياً على سيرفر حقيقي للتأكد إنها بتنجح من أول
محاولة** (يحتاج Docker + مساحة تخزين حقيقية غير متوفرة وقت كتابة
هالملفات). يعني الخطوات صحيحة نظرياً وموثقة رسمياً، بس التنفيذ الفعلي
لازم يتأكد منه اللي بيشغّلها.

## الإعداد (مرة وحدة بس، قبل أول تشغيل)

محتاج Docker مثبّت على السيرفر مسبقاً.

```bash
bash setup.sh
```

بيحمّل بيانات خرائط سوريا (من Geofabrik، مصدر مجاني) ويجهزها لصيغة
OSRM. بياخد كذا دقيقة أول مرة.

## التشغيل

```bash
docker compose up -d
```

بيشغّل خدمة OSRM على بورت `5000`.

## ⚠️ خطوة لازمة — كشف OSRM على رابط عام

الخدمة لازم تنكشف على رابط عام بـ HTTPS (subdomain)، مثلاً
`osrm.waselni.alttair.tech`، بنفس الطريقة يلي `waselni.map.alttair.tech`
مكشوفة فيها (reverse proxy عبر nginx/Caddy لبورت 5000).

**السبب**: صفحة الخريطة بتشتغل على موبايل كل مستخدم لحاله (WebView)،
مش على السيرفر — يعني كل طلب OSRM بيطلع مباشرة من موبايل المستخدم عبر
الإنترنت، مش من داخل الشبكة الداخلية للسيرفر. بدون هالخطوة، OSRM بيضل
شغال بس محدّش يقدر يوصله.

## بعد ما توصل الخدمة على رابط عام

ابعتوا الرابط لفريق تطبيق الموبايل/الخريطة حتى يربطوها بصفحة الخريطة
(`yabroud-bus-system-map`) بدل الخدمة الخارجية الحالية.

## تأكيد

بعد التشغيل، جربوا طلب مباشر متل هيك (بدّلوا الرابط والإحداثيات):

```bash
curl "http://localhost:5000/route/v1/driving/36.6521719,33.9745185;36.6610,33.9620?overview=full&geometries=geojson"
```

لو رجع رد فيه `"code":"Ok"` ومسار (`geometry`)، الخدمة شغالة صح.

## لو صار عطل بـ OSRM

صفحة الخريطة عندها fallback تلقائي: لو فشل الطلب لأي سبب، بترجع ترسم
نقاط المحطات الخام مباشرة كخط مستقيم بدل ما يختفي المسار كلياً.
